## Automatic checkpoint procedure

After each meaningful implementation milestone:

1. Save all modified project files.
2. Update relevant documentation.
3. Run appropriate checks.
4. Inspect Git status and the change diff.
5. Commit completed, verified changes to Git.

Use descriptive commit messages such as:

- `feat: establish Verdana design system`
- `feat: implement homepage hero`
- `feat: complete responsive navigation`
- `feat: add Business Central services`
- `feat: implement ERP cost calculator`
- `fix: resolve mobile layout issues`
- `docs: update deployment requirements`

Checkpoint after meaningful deliverables, not every individual line of code.

Do not create commits containing broken code unless explicitly documenting a recoverable work-in-progress checkpoint.

Never overwrite unrelated existing changes.

Never use destructive Git commands, force pushes or history rewriting without authorization.

Never commit secrets, credentials or environment-specific private configuration.

If remote Git synchronization is configured and authorized, push verified checkpoints according to the established repository workflow.

Local commits alone do not protect against loss of the local computer, so recommend remote backup when appropriate.

- Save the current status.

1. Read `CLAUDE.md`.
